# Interview Methodology

Goal: turn open-ended questions into a design process that is easy to communicate, validate, and explore in depth. This module focuses on how to conduct a system design interview; later modules cover specific component principles and complete case studies.

## Recommended Order

- [Conducting a System Design Interview](01-how-to-conduct-a-system-design-interview.md)
- [Requirements Clarification and Scope Control](02-requirements-clarification-and-scope-control.md)
- [From APIs to a High-Level Architecture](03-from-apis-to-a-high-level-architecture.md)
- [Finding Bottlenecks and Diving Deep](04-finding-bottlenecks-and-diving-deep.md)
- [Common Mistakes and Evaluation Criteria](05-common-mistakes-and-scoring-criteria.md)

## Learning Outcomes

- Turn an open-ended prompt into a clear scope within a few minutes.
- Use estimates, APIs, data models, and data flows to establish a high-level design.
- Choose the most important areas for a deep dive instead of giving every component equal coverage.
- Explain design decisions, failure behavior, and the system's evolution path.
- Review a mock interview using consistent criteria.
