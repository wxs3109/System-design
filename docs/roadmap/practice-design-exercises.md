# 综合设计练习候选计划

> 状态：候选方向，未开始实现；优先级待结合后续产品想法确定。记录日期：2026-09-06。

本题是[学习能力矩阵](./learning-capability-matrix.md)中的 CASE-01 候选切片。整体能力覆盖和建议学习路径由矩阵维护，本文保留该题的具体范围；不预设它先于基础 Lab 实现。

## 目标

现有三道练习覆盖服务排队、数据库瓶颈和缓存压力，主要允许在固定拓扑上调整参数。候选的下一步是让用户根据需求选择组件、连接请求路径，并用运行证据解释设计取舍。

首个候选题：**URL Shortener — 搭建短链接跳转的读取路径**。

## 首题范围

- 给定已有短码集合、固定读取负载、简化处理耗时和性能目标。
- 用户添加、连接 Service、Database，可选 Cache，并调整题目允许的配置。
- 锁定流量、运行条件和必要模型假设，声明可用组件及资源边界。
- 支持至少两种达标方案，例如较强 Database 直接读取，以及 Cache 配合较小 Database；比较排队、延迟、数据库读取量和资源配置。
- 结果用于学习模型下的路径与容量分析。短码生成、唯一性、并发更新、写入一致性及完整短链业务正确性留给后续关卡，不部署真实组件。

具体负载、参数范围和评分阈值在开始实现时通过可复现仿真校准，当前不预设数值或云资源价格。

## 最小实现范围

1. **题目级编辑规则与工具箱**：声明允许添加的组件、可编辑配置和受保护节点；继续通过统一项目编辑命令处理修改、撤销与保存。
2. **结构检查**：从用户拓扑解析节点角色和连接语义，检查必要访问路径及资源边界。保留现有参数练习的固定拓扑约束，综合题按规则接受不同拓扑。
3. **请求路径证据**：核验每个请求实际完成数据库访问，或具有有效的缓存命中证据。缓存未命中必须走正确的数据库读取路径；仅有低延迟或成功终态不足以通过。
4. **比较与复盘**：结合配置和实际运行指标呈现不同方案的取舍，支持用户解释修改原因与效果。

复用现有画布、组件行为、Workbench Session、仿真引擎、本地历史和结果比较。题目规则放在练习模块，仿真内核保持通用；首题不以新增组件、通用规则语言或整套课程系统为前置条件。

## 验收条件

- [ ] 用户能从初始场景自行搭出至少两种不同的达标拓扑，无需复制唯一标准图。
- [ ] 无数据库、绕过数据库且无有效缓存命中、错误缓存未命中路径均不能通过，并有具体反馈。
- [ ] 评分引用当前设计的完整运行证据；截断、缺失或不匹配的证据不能通过。
- [ ] 修改拓扑或配置后旧结论失效，重新完整运行才能验证新设计。
- [ ] 支持运行、比较和复盘；刷新恢复设计与尝试记录，各题及自由工作台互不覆盖。
- [ ] 原有三道练习继续通过相关检查，新增能力有路径验证测试及浏览器流程覆盖。

## 后续决策

先结合新的产品想法确定是否启动本计划。若完成首题，再安排少量目标用户试做，观察能否独立完成并解释设计差异，以此决定后续题库方向。

本计划与[需求和容量规划](./demand-capacity-planning/README.md)分别确定范围与优先级；当前模型边界以[仿真模型说明](../model-assumptions.md)为准。
