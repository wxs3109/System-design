# 基础设计决策：顶层设计与交付计划

日期：2026-09-27。定位：学习和研究系统设计，用有限模型理解限制、选择与代价。本文管理教学交付；[学习能力矩阵](./learning-capability-matrix.md)继续维护全域覆盖，[ADR-002](../decisions/adr-002-experiment-core.md)继续约束工程架构。

## 学习目标

学习者能沿着“需求 → 成功标准 → 资源与状态约束 → 选择机制 → 故障/负载实验 → 检查证据和代价”解释设计。可靠性、可用性、持久性、一致性、性能、可扩展性、可维护性与成本分别定义，不把它们缩成统一的三个指标，也不按组件或厂商名称判定答案。

## 教学分层

1. **知识页**：最小问题、约束、成立条件、反例、自测；补充“适用条件 / 可考虑的选择 / 要承担的代价”。正文独立阅读，不自动记为通过。
2. **机制与决策 Lab**：一次只验证一个有限问题；固定需求，改变策略，保留完整输入及证据。通过必须来自模型事实，不能仅检查策略名或选择题选项。
3. **综合设计题**：组合已经解释过的能力，复用知识页和模型；不会因为存在某个案例就标记整个基础领域已完成。

基础路径继续使用 `/learn?path=design-foundations`，知识页继续使用 `/learn/[conceptId]`，实验继续使用 `/practice/[exerciseId]`。不增加平行课程系统、独立进度数据库或另一套实验路由。

## 代码边界与复用规则

- `features/learning` 维护知识元数据、正文与路径。新增可选 `decisionGuide` 字段，由现有文章模板统一呈现，不为每篇另写页面。
- 每个新 Lab 使用 `features/practice/<lab>/model.ts`、`lesson.ts`、页面适配和测试。模型只产生事实，教学说明与验收由 lesson 负责，React 负责展示。
- 首个 Lab 复用已有泛型 `ProtocolExperiment` 和 `AnswerFields`。该组件已经接受模型、配置、证据和判据适配，基础决策无需再实现一套按钮、历史、保存与反馈。
- 会话、撤销、备份、版本、错误恢复复用 `core/experiments` 与 `components/experiments`；按已有 registry 绑定入口，不给动态路由增加 ID 分支。
- 只有两个实际消费者出现同一种重复逻辑时才抽取通用助手。不同语义的模型保持独立；不通过一个含大量题目分支的“基础万能模型”组织内容。
- 既有数据库 scope、模型/评分版本和已发布知识 ID 保持稳定；新实验独立命名、声明版本和操作预算。
- 一切“可运行”入口从应用注册表产生。未交付批次只在本文/能力矩阵中标注计划，不展示可点击的虚构实验。

## FD-1 详细规格

### 知识与路径

新增 `quality-goals`、`resource-constraints`、`capacity-estimation`、`storage-access-patterns`、`state-and-scaling` 五篇。每篇包含原文章合同全部字段和 2–3 条选型指导；关联已有 Lab 时注明其验证范围。基础路径先读这五篇，再进入已有缓存、异步、并发与恢复内容。

### quality-goals 模型

最多两个服务实例、两个故障域、一个独立的符号存储和一个可选依赖，最多 40 个操作。服务副本只保护服务实例，不能自动增加存储副本。存储有易失与稳定集合，写入确认策略为仅内存或先稳定保存；崩溃清空易失状态，重启从实际稳定集合恢复。

客户端请求形成有身份、返回内容类别、延迟和故障背景的账本。降级返回核心内容与完整返回分开记录；是否满足要求由固定挑战合同决定。失败请求始终保留在分母中，空请求集合不能显示 100% 可用。时间和延迟为声明的教学常数，不是实测或 SLA 估计。

三个挑战：

1. **故障窗口仍可用**：相同请求脚本经过一个故障域不可用及恢复，要求核心服务在约定延迟内返回；同域双副本必须暴露共同故障。
2. **确认成功以后数据还在**：完成两个写入，再崩溃/恢复存储；比较确认账本与实际恢复集合。增加服务副本不能代替持久化。
3. **依赖失败与降级边界**：相同脚本使附加依赖失败；分别报告完整返回、核心内容降级和失败。该挑战明确允许核心内容降级，同时展示若要求完整内容则不满足。

每关可单步、自由操作、重放、同条件对照和保存恢复。检查同时要求真实执行到相应故障窗口、满足业务保证及正确解释证据；跳过故障、减少请求、只填写正确文字都不能通过。

## FD-2 详细规格

`resource-budget` 独立 Lab 将单位推导与实际资源账本连接。业务输入为离散的用户数、每日操作、峰均比、读比例、响应 bytes、保留天数及副本数；资源为 1/2/4 个计算与存储槽，以及 8/80/800 Mbps 的共享响应链路。固定 5 秒到达窗口、最多 1000 个请求，逐请求预约三个串联资源，继续排空而不删掉慢请求。

计算每次 50 ms、存储每次 100 ms，网络按响应 bytes / 共享速率排队；不持有上游槽等待下游。观察完整样本 p95、各段等待、窗口内完成数和真实在途时间积分。长期写入按读写比例与保留期推导，区分十进制 MB 与 Mbps、平均与峰值。三个挑战分别验证单位、网络瓶颈与存储瓶颈，固定需求后允许多种满足条件的资源选择。

该模型只实现本教学切片；DP-01 至 DP-20 的完整容量规划、项目应用与事务回滚保持原状态。新 Lab 与 quality-goals 共同复用类型化配置控件，其余执行、历史和评分直接复用原实验壳。

## FD-3 详细规格

`data-access-paths` 使用 16 条实际记录、主键字典和 owner/time/id 有序条目，复用平台关系数据合同。分别执行强制扫描、主键定位和二分定位后的范围读取，记录实际返回、源数据快照、读取记录、索引探测和 UTF-8 载荷字节。四关为点查、用户时间列表、更新后的索引完整性、元数据与内容读取分离。

记录更新可同步维护二级索引，也可等待显式刷新；历史查询保留当时结果，后续修复不能抹去反例。参考结果直接枚举查询时的源快照，不由索引候选计算。有限模型不执行通用 join、多行事务、真实 B+ Tree 或厂商性能比较，相关需求仍通过已有讲解与事务 Lab 连接。

## FD-4 详细规格

`state-placement` 使用两个符号用户、最多两个实例和一个共享存储，实际读写会话值。轮询与固定首选实例分别选路，首选失败时切换到健康实例；实例崩溃清空本地状态，共享进程重启只恢复实际稳定集合。客户端确认账本只观察，不修补数据。

三个挑战为正常路由、服务崩溃后接管、共享存储重启。正常条件下本地亲和与共享状态都可能有效；接管后必须重新验证，共享存储恢复期间的不可用与值丢失分别记录。身份可信、请求串行、路由即时感知在线状态，不模拟真实连接或负载均衡协议。

## 验收与发布

模型需要确定性/不修改输入、边界预算、反例、JSON 往返、证据篡改拒绝和独立期望值测试。页面需要验证从知识入口到 Lab 的完整路径、策略改变后的失效提示、历史恢复与窄屏可用性。原实验继续通过回归，依赖检查约束不放宽。

每批完成后更新本文与能力矩阵，执行相关测试及完整 `pnpm check`，再 commit、push。每批报告实际交付范围，未实现部分继续标为计划。
