# DP-08: Sessions, CDN, and Object Storage transfer

> Status: not started. Depends on DP-07. Completes M3.

[Roadmap and part index](./README.md) · [Shared contracts](./shared-contracts.md)

## Outcome and scope

Model sustained sessions separately from transactional bodies, and bind CDN edge/origin and Object Storage read/write throughput to shared resources. This part covers transfer capacity; stored-data capacity follows DP-09/DP-10, and Realtime connection state follows DP-16.

## Input and output contract

Extend versioned demand activities with a session contract: fixed concurrent sessions or session-start rate, mean/fixed duration, initial active cohort, ingress/egress bitrate per session, lifecycle profile, and explicit delivery-path binding. Session-start operations may have control-request bytes; continuous content has separate ownership and is not duplicated as response payload.

For an explicitly stationary fixed-concurrency scenario, derived start rate is `C / meanDuration`. Record that stationarity assumption and initialize the active cohort; starting an empty runtime at that rate does not immediately produce C sessions. A nonstationary scenario supplies starts and duration/lifetime cohorts and derives concurrency over time. Peak multipliers specify whether they affect starts, concurrent sessions, or bitrate.

CDN inputs include POP distribution, cache/byte-hit assumptions, edge pools and origin pools. Object Storage inputs include operation-specific object size and separate read/write pools. Adapters expose each dimension's versioned support and appropriate current/proposed bandwidth controls. Server count and cache working-set sizing are separate parts.

## Execution rules

- Session cohorts contribute integrated byte demand to DP-06 pools; do not emit one request per byte or fake concurrency from API latency. Bound cohort count and change points. Oversized discrete lifecycle work is rejected by preflight or requires an eligible aggregate mode later.
- The initial implementation uses fixed duration and explicit cohorts. Residual lifetimes of an initial stationary cohort are explicitly supplied or generated by a documented deterministic spread; arbitrary lifetime distributions remain unsupported.
- A session's delivery path charges active edge egress and any origin/read work under declared semantics. Per-session playback progress cannot exceed served bytes; report offered bitrate, achieved bitrate, delayed bytes, and ended-session discarded bytes.
- Store-and-forward transfer may buffer to a configured bound. Live/latest-data delivery may drop excess or stale bytes using an explicit maximum buffer age. Neither policy silently retains infinite work after a session ends.
- CDN origin demand uses byte miss ratio, not request miss ratio. Analytic assumptions and discrete observed cache outcomes remain separate. A fixed byte-hit assumption in an aggregate delivery scenario is labeled an assumption, not observed cache behavior.
- This part introduces a versioned CDN traversal contract for operation-aware delivery paths, reusing the same cache lookup/fill ownership as capacity-only delivery. Each miss executes its bound origin dependency once; a successful origin result fills only the selected POP. Upgrade is explicit. Legacy operation paths without that contract cannot claim cache validation.
- Object Storage consumes actual resolved object/request work according to operation type. Remove old per-request throughput delay when the shared pool is enabled. Metadata latency and request concurrency remain separate limits.
- Multiple POPs may share a node-local origin pool. Cross-node shared pool IDs remain deferred; list the pool ownership explicitly.

## Acceptance cases

1. 1,000 active sessions at 2,000,000 bits/s require 2,000,000,000 bits/s edge egress. At a declared 90% byte-hit ratio, estimated origin egress is 200,000,000 bits/s.
2. A stationary cohort of 1,000 sessions with 100-second duration has expected starts of 10/s. An empty-start scenario ramps according to its lifetime model instead of instantly asserting 1,000 active sessions.
3. The same request hit ratio with different object-size mixes produces different byte hit ratios and different origin demand.
4. Two simultaneous Object Storage reads share its read pool; a write uses the separate write pool. Size overrides change served bytes and completion duration.
5. A 1-Gbit/s edge under 2-Gbit/s offered session traffic reports achieved rate, backlog or policy drops, and degradation. Increasing edge bandwidth exposes any unchanged origin constraint.
6. Control-request bytes and continuous content reconcile separately; session end and cancellation conserve served, dropped, and remaining bytes.
7. A generic capacity-only delivery fixture and a supported operation-aware fixture use the same demand contract with no example-name branch.
