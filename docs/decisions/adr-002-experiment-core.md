# ADR-002：教学实验核心与兼容边界

日期：2026-09-26。状态：实施中。

本轮只整理底层架构，不新增案例，也不要求所有教学模型使用同一个仿真引擎。

## 目标与交付顺序

1. 将通用会话、存储接口、协议实验适配与错误处理移到中立核心模块，消除核心依赖具体题目。
2. 分离产品模型的语义结果、验收结果和展示投影；展示文字与图形变化不得使语义证据失效。
3. 建立独立的模型、题目、评分和记录格式版本；旧记录保留，迁移有明确入口，未知版本拒绝覆盖。
4. 统一实验运行生命周期与保存保护；画布 Worker 和纯函数保留各自执行方式，通过明确接口接入。
5. 收敛实验注册、按需加载与类型/依赖约束；自动检查注册完整性和模块边界。

每部分完成后先验证，再单独 commit、push。记录格式变化必须验证已有浏览器数据恢复、历史不可变、并发保存冲突和不匹配版本处理。

## 依赖方向

- `core/experiments`：会话、运行与存储接口、兼容策略；不依赖具体教学题目或 React 页面。
- `features`：题目内容、纯教学模型、模型适配与展示投影。
- `components/experiments`：共享 React 展示；通过核心接口操作会话。
- `packages/simulation`：保留画布编译/Worker 引擎；不导入应用题目。

稳定数据库名称和 scope 属于兼容协议，移动源码或重命名类不得改变它们。

## 第一部分：中立实验核心

已将通用合同、会话、IndexedDB 实现、协议 lesson 工厂及相等判断移入 `core/experiments`，共享保存提示移入 `components/experiments`。会话只依赖 `ExperimentRepository` 接口；增加内存实现测试，确认不需要 IndexedDB 即可运行会话流程。所有原数据库名称、scope、记录格式和历史语义保持一致。

验证：类型检查、lint 和构建通过；480 项 Web 单元测试及 18 项保存恢复/画布/协议/产品浏览器回归通过。首次同时运行构建和测试导致既有 Hot Key 5 秒测试预算超时，串行重跑全部 Web 测试通过；后续 CPU 密集检查顺序执行，不提高原测试超时。

## 第二部分：产品语义证据与展示分离

五个业务模型移入 `features/design/models`，只返回状态、结构化观察和指标；中文事件说明、表格、布局移入 `presentation`。模型更新只改变事实，展示投影负责呈现。产品尝试使用记录格式 v2，分别保存 model/definition/assessment 版本及机器可读的检查结果，取消按中文内容过滤协议提示的适配。

原 v1 模型和验证器冻结在 `compat/v1`，保存原记录原样并使用原算法校验；兼容的 v1 进度继续有效。不同版本的结果明确显示历史身份，不冒充当前版本通过。未知或不匹配记录不会被当成有效当前结果。

验证：491 项 Web 测试通过；包括五模型所有场景、参考方案及确定性生成操作序列与 v1 的逐项对照、JSON 往返、语义篡改拒绝、改变展示不影响核验、旧 IndexedDB 记录原样保留。六项产品/旧格式浏览器回归通过，lint、类型检查、构建通过。旧协议 Lab 的兼容外形与统一迁移策略在下一部分处理。

## 第三部分：版本迁移与历史保留

草稿记录升级为 v2，分开标记草稿 Schema 与 model/definition/assessment 版本。迁移只能通过声明的逐版本函数进行；读取不写回，首次保存时保留迁移前原稿。未知格式、未来草稿版本、缺失迁移和未声明的模型切换均阻止覆盖。尝试记录也保存来源版本，不把旧评分版本静默当作当前通过。

无法核验的历史仍留在 IndexedDB，恢复导出包含原始记录；读取失败也能导出已读取的恢复材料。旧协议 Lab 保持兼容线格式，明确将时间线说明和评分文案视为展示缓存，只有声明的语义投影参与核验；请求内容、事件身份/顺序/时间、状态和判定标志仍完整核对。

验证：495 项 Web 回归通过；补充记录头检查后相关 30 项测试通过。17 项浏览器恢复/旧格式/协议/产品回归通过；类型检查、lint、构建通过。
