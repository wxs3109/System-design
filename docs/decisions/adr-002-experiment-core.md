# ADR-002：教学实验核心与兼容边界

日期：2026-09-26。状态：已实施。

本轮只整理底层架构，不新增案例，也不要求所有教学模型使用同一个仿真引擎。

## 目标与交付顺序

1. 将通用会话、存储接口、协议实验适配与错误处理移到中立核心模块，消除核心依赖具体题目。
2. 分离产品模型的语义结果、验收结果和展示投影；展示文字与图形变化不得使语义证据失效。
3. 建立独立的模型、题目、评分和记录格式版本；旧记录保留，迁移有明确入口，未知版本拒绝覆盖。
4. 统一实验运行生命周期与保存保护；画布 Worker 和纯函数保留各自执行方式，通过明确接口接入。
5. 收敛实验注册、按需加载与类型/依赖约束；自动检查注册完整性和模块边界。

每部分完成后先验证，再单独 commit、push。记录格式变化必须验证已有浏览器数据恢复、历史不可变、并发保存冲突和不匹配版本处理。

## 依赖方向

- `core/experiments`：会话、运行与存储接口、兼容策略；不依赖具体教学题目或 React 页面。
- `features`：题目内容、纯教学模型、模型适配与展示投影。
- `components/experiments`：共享 React 展示；通过核心接口操作会话。
- `experiments/registry.ts`：服务端组装入口，绑定具体题目与按需加载的页面；目录、路由和已发布案例从这里派生。客户端只导入各自的题目入口。
- `packages/simulation`：保留画布编译/Worker 引擎；不导入应用题目。

稳定数据库名称和 scope 属于兼容协议，移动源码或重命名类不得改变它们。

## 第一部分：中立实验核心

已将通用合同、会话、IndexedDB 实现、协议 lesson 工厂及相等判断移入 `core/experiments`，共享保存提示移入 `components/experiments`。会话只依赖 `ExperimentRepository` 接口；增加内存实现测试，确认不需要 IndexedDB 即可运行会话流程。所有原数据库名称、scope、记录格式和历史语义保持一致。

验证：类型检查、lint 和构建通过；480 项 Web 单元测试及 18 项保存恢复/画布/协议/产品浏览器回归通过。首次同时运行构建和测试导致既有 Hot Key 5 秒测试预算超时，串行重跑全部 Web 测试通过；后续 CPU 密集检查顺序执行，不提高原测试超时。

## 第二部分：产品语义证据与展示分离

五个业务模型移入 `features/design/models`，只返回状态、结构化观察和指标；中文事件说明、表格、布局移入 `presentation`。模型更新只改变事实，展示投影负责呈现。产品尝试使用记录格式 v2，分别保存 model/definition/assessment 版本及机器可读的检查结果，取消按中文内容过滤协议提示的适配。

原 v1 模型和验证器冻结在 `compat/v1`，保存原记录原样并使用原算法校验；兼容的 v1 进度继续有效。不同版本的结果明确显示历史身份，不冒充当前版本通过。未知或不匹配记录不会被当成有效当前结果。

验证：491 项 Web 测试通过；包括五模型所有场景、参考方案及确定性生成操作序列与 v1 的逐项对照、JSON 往返、语义篡改拒绝、改变展示不影响核验、旧 IndexedDB 记录原样保留。六项产品/旧格式浏览器回归通过，lint、类型检查、构建通过。旧协议 Lab 的兼容外形与统一迁移策略在下一部分处理。

## 第三部分：版本迁移与历史保留

草稿记录升级为 v2，分开标记草稿 Schema 与 model/definition/assessment 版本。迁移只能通过声明的逐版本函数进行；读取不写回，首次保存时保留迁移前原稿。未知格式、未来草稿版本、缺失迁移和未声明的模型切换均阻止覆盖。尝试记录也保存来源版本，不把旧评分版本静默当作当前通过。

无法核验的历史仍留在 IndexedDB，恢复导出包含原始记录；读取失败也能导出已读取的恢复材料。旧协议 Lab 保持兼容线格式，明确将时间线说明和评分文案视为展示缓存，只有声明的语义投影参与核验；请求内容、事件身份/顺序/时间、状态和判定标志仍完整核对。

验证：495 项 Web 回归通过；补充记录头检查后相关 30 项测试通过。17 项浏览器恢复/旧格式/协议/产品回归通过；类型检查、lint、构建通过。

## 第四部分：执行会话与画布保存保护

本地实验和画布 Worker 共用执行所有权/取消控制；异步结果必须匹配原输入，旧执行不能更新新状态。共享 React 会话挂载和纯模型预览缓存复用已有执行结果，避免编辑校验与渲染重复计算。

连续的同步编辑合并一次自动保存，避免对同一份大结果重复复制和排队；显式保存立即提交当前状态，旧请求完成仍不能覆盖新的保存状态。恢复过程中显示忙碌提示并禁止编辑，成功读取后恢复鼠标与键盘操作。

画布每个会话拥有独立存储写入游标。数据库 v3 将当前保存指针与旧客户端指针隔离，事务内校验修订号；读取失败、未知版本和多标签页冲突暂停编辑，并提供保留记录导出及明确重新读取。保存失败保留本地修改。运行记录标记存储/引擎版本，未知结果保留并从当前展示及清理中排除。

同步 JavaScript 仍依靠模型预算限制工作量；共享取消接口不宣称可以抢占已经执行的同步函数。重模型可通过已有 Worker/异步接口接入。

验证：503 项 Web 测试通过；补充保留未知运行测试后相关 14 项测试通过，226 项仿真引擎测试通过；17 项浏览器回归覆盖画布读失败、双标签页、恢复导出、旧版本保护、原实验与布局。lint、类型检查和构建通过。

## 第五部分：统一注册与自动架构约束

18 个基础 Lab 与 6 个综合设计题在应用注册表统一绑定元数据、执行能力、案例关联和加载入口。练习目录、已发布案例、知识页链接及动态路由均使用该注册表；页面不再按题目 ID 分发。产品题通过独立客户端入口加载，只携带本题模型及对应的旧版本读取器。

`defineProductDesign` 将配置字段及选项、操作名称、模型结果、指标和版本关联起来。新增题目的拼写错误或不兼容定义在类型检查时拒绝；运行入口再检查传入配置、操作预算与模型版本。通用 UI 所需的类型擦除集中在这个边界，题目内部仍使用具体结果类型。

`pnpm lint` 运行依赖检查：核心不得反向依赖页面或题目，纯模型不得导入 UI/存储，展示不得执行模型，下层包不得导入 Web 应用，客户端不得间接载入完整实验注册表。冻结的 v1 兼容源通过校验和保护。检查器自身包含正反例自测，类型检查也包含必须编译失败的非法题目定义。

验证：507 项 Web 测试、类型检查、lint 和生产构建通过；7 项定向浏览器测试覆盖全部 24 个实验路由、未知路由、知识关联与旧产品记录恢复。依赖检查器的 7 个自测通过。

## 最终验收

完整 `pnpm check` 通过：866 项单元测试（其中 Web 509 项）、106 项浏览器测试，以及内容/依赖检查、类型检查和生产构建。浏览器回归覆盖全部实验路由、旧记录恢复、多标签页冲突、读写失败恢复、慢读取期间的编辑保护和键盘操作。回归发现的重复自动保存及恢复期间缺少状态提示已修复；测试仍使用原有超时限制。

## 后续扩展约定

1. 新模型声明输入、有限状态、操作预算和版本，只产生可重算事实；评分根据事实判定，文案与图形由展示投影生成。
2. 新实验接入共享会话和存储接口；纯函数与 Worker 可独立选用，保留取消、过期结果拒绝及恢复保护。
3. 在应用注册表绑定题目和独立页面入口。知识关联仍由概念索引维护，不在路由中增加题目专用分支。
4. 改变模型、题目或评分语义时更新相应版本；草稿结构变化提供显式迁移。旧历史保留，兼容判定必须有对应读取器，不能直接改写旧格式实现。
5. 运行完整 `pnpm check`；它包含内容/依赖检查、类型检查、单元测试、生产构建和浏览器回归。

这些接口服务于有限的教学实验。统一的是生命周期、证据与兼容合同，不要求所有模型具有真实中间件的实现细节或相同的运行引擎。

## 持续使用加固：历史与备份

Lab 数据库 v3 为历史增加时间与归档索引，保留原尝试内容。首次打开只核验最近 10 条及当前结果；历史列表直接读取索引摘要，选中旧记录后才重放核验。页面进度明确仅包含已载入核验的记录。归档可撤销，永久删除需要选择已归档且未使用的记录并再次确认；管理操作沿用修订号冲突保护。

Lab 和工作台支持备份导出、只读预览、确认导入。导入校验格式、范围、版本和记录身份，同名内容冲突会回滚整个导入；原草稿作为恢复材料保留。未知 Lab 证据保留且排除评分，工作台导入的运行结果标记为外部历史，重新运行后才能参与练习判定。设计笔记作为独立范围，有自己的备份入口。

验收覆盖 1,000 条历史的有界读取、无模型重放的分页、按需核验、归档/删除、多标签页冲突、损坏及未知记录保留，以及在全新浏览器中导入备份后刷新恢复。

本部分验证：872 项单元测试（Web 515 项）、108 项浏览器测试、lint、类型检查和构建通过。首次浏览器全量检查有一次既有连线名称显示断言失败；该测试连续三次专项重跑及随后整套 108 项重跑通过，未调整测试超时或删除断言。

## 持续使用加固：异常隔离与运行预算

实验页面和自由工作台接入 React 错误边界。会话及恢复入口位于出错子树之外：重新显示会复用内存中的当前输入，不自动载入旧草稿。实验、设计笔记和工作台分别提供导出及明确舍弃本页修改后重读的入口。完整备份无法读取时仍可导出本页输入，并标明文件不完整。

最大 Hot Key 输入（4,096 keys、20,000 次读取、每节点 128 tokens、256 条缓存）在本机 Node 的三次测量中，计算为 162–242 ms，核验为 204–224 ms。这是界面主线程的明显阻塞，因此 Hot Key 计算及持久化证据核验已迁入 Worker；其余轻模型保留原执行方式。单次 Lab Worker 计算/核验预算为 5 秒，画布 Worker 运行预算为 30 秒。超时、取消或错误均终止对应 Worker，保留输入；旧结果不能覆盖新输入。核验 Worker 的暂时故障作为可重试读取失败，不把已有历史判作损坏。

已保存结果在会话中保留有限工作集，其余留在数据库按需读取；达到 20 条未保存结果后暂停新增计算，避免存储故障时无限堆积。完整历史导出逐条读取，正文预算为 25 MiB，含当前状态的文件预算为 50 MiB；过大记录集合可使用单条导出。导入沿用 50 MiB 文件及 10,000 条记录上限。

连线高亮测试的直接文件注入和事件派发会绕过浏览器的可操作性检查，现已在这些操作前等待工作台恢复完成，并单独验证输入框确实收到名称；保留原有高亮断言和超时。

最终完整 `pnpm check` 通过：878 项单元测试（Web 520 项、仿真引擎 227 项）、111 项浏览器测试，以及 lint、依赖检查、类型检查和生产构建。新增浏览器验收实际注入渲染异常、保存失败及 Worker 挂起，验证未保存内容导出、保留输入重试、刷新恢复和超时后继续运行。
